# Whyzy

Voice-first, safe AI assistant for children aged 4+. Invite-only pilot.

- Product spec: `SPEC.md`. Requirements: `REQUIREMENTS.md`. Read both before changing behaviour.
- Build in the phases in `SPEC.md` (1–7 done; 8–11 add content cards), one phase per session. Commit and deploy at the end of each phase.
- Never use real children's data during build or test. Use made-up data only.

## Decisions that differ from SPEC.md

- Login is email and password (Auth.js Credentials, JWT sessions) for now. OAuth (Google) comes later. The Drizzle adapter and its tables are already there for that.
- Password reset by SMTP email comes later. The operator will share the email service details.
- Replies are always in English. A child profile sets the input language (English or Hindi).
- Whyzy is card-first: pre-written, validated content (stories, poems, rhymes, good and bad habits, more). Chat is optional, off by default; audio only by default. Content is generated by the operator only, never while a child uses the app.

## Data hygiene rules (always)

- Never log prompts, replies, names, emails or other personal details. Log IDs and event types only.
- No analytics, no telemetry (`NEXT_TELEMETRY_DISABLED=1`), no ads, no behavioural tracking.
- Vercel Functions run in `bom1` (`vercel.json`). Turso databases must be in Mumbai (`aws-ap-south-1`).
- Secrets live in `.env.local` (git-ignored) and Vercel environment variables. Never commit them.
- Access keys are stored as SHA-256 hashes only.

## Commands

- `npm run dev` / `npm run build` / `npm test` / `npm run typecheck` / `npm run lint`
- `npm run turso:setup`: create the central DB in Mumbai, write its URL and token to `.env.local`
- `npm run db:generate`: create a migration after editing `src/db/central/schema.ts`
- `npm run db:migrate`: apply migrations to the central DB
- `npm run keys:create -- <count> <days>`: create pilot access keys (printed once)
- `npm run content:migrate`: apply content DB migrations and sync modules and collections
- `npm run content:seed`: load `content/seed/*.json` as drafts
- `npm run content:validate`: check all drafts (rules, then LLM validator) and auto-publish the ones that pass
- `npm run content:generate -- <module> <collection> <age-band> <count>`: generate, check and publish (operator only)
- `npm run content:narrate`: make and store narration (ElevenLabs) once for published parts missing it; validate and generate also run it

## Layout

- `src/db/central/client.ts`: `CENTRAL_DB_URL`/`CENTRAL_DB_TOKEN` win over `TURSO_*` (Vercel's Turso integration branches a DB per deployment; production pins the main DB).
- `src/auth.ts`: Auth.js config. `src/lib/dal.ts`: session check (call inside `<Suspense>`; Cache Components are on).
- `src/db/central/`: central DB schema and client. `drizzle/central/`: migrations.
- `src/lib/access-keys.ts`: invite keys and parent registration (one transaction).
- `src/lib/turso-platform.ts`: Turso Platform API (setup and family DBs).
- `src/db/family/`: family DB schema. `drizzle/family/`: its migrations, applied when a family DB is opened.
- `src/lib/family-db.ts`, `src/lib/family.ts`: create, open and drop family DBs; account deletion.
- `src/lib/child-mode.ts`: signed child-mode cookie; parent area needs the PIN while it is set.
- `FAMILY_DB_LOCAL_DIR`: local SQLite family DBs for development and tests only.
- `src/lib/ai/`: model config (`WHYZY_PROVIDER` gateway|openrouter, `WHYZY_MODEL`, `WHYZY_STAGE`) and age-band system prompt. All model calls go through `languageModel()`. OpenRouter is test-only; pilot requires AI Gateway.
- `npm run models:free`: check which free OpenRouter models answer with this key; writes `docs/FREE_MODELS.md`.
- `src/lib/chat/`: chat service (limits, model call, logging); `src/app/api/chat/route.ts`: child chat API.
- `src/lib/safety/`: input filter (rules, PII stripping, intent), fixed replies, output moderation.
- `tests/redteam/cases.json`: versioned red-team set; `tests/redteam.test.ts` runs it in `npm test`, CI and every Vercel build. `npm run redteam:live` runs it against the real model.
- `src/lib/voice/`: on-device push-to-talk (`processLocally = true`, no cloud fallback), TTS (`WHYZY_TTS`: ElevenLabs via AI Gateway by default, or direct with a key or Vercel Connect connector); `src/app/api/tts/route.ts` speaks only server-signed replies.
- `src/app/child/`: child mode. `child-app.tsx` (home of module cards, module shelves, player, chat, pet picker, wind-down), `cards.tsx` (card styles adapted from the Figma "Storytelling App Design for Kids"; theme in `globals.css` `.wz-*`), `player.tsx` (stored narration, device voice fallback), `chat-view.tsx`. Audio-only mode shows no text; `src/lib/avatar.ts`: avatar states and sprite manifest; `src/lib/pets.ts`: approved pets.
- `src/db/content/`: content DB schema and client (`CONTENT_DB_URL`/`CONTENT_DB_TOKEN`); `drizzle/content/`: its migrations (`npm run content:migrate` also syncs modules).
- `src/lib/content/`: module list and library (drafts, status changes, published-only reads); `src/app/api/content/route.ts`: child library API.
- `content/modules/<module>/AGENT.md` + `SKILL.md`, `content/validator/AGENT.md`: versioned agent files (front matter `version`). Bump the version when you change one.
- `content/seed/`: hand-written seed items (plus traditional public-domain rhymes).
- `src/lib/content/generate.ts` (`CONTENT_MODEL`), `validate.ts` (`CONTENT_VALIDATOR_MODEL`): pipeline. Validator errors leave items as drafts; failed checks reject them.
- `src/lib/content/narrate.ts` + `src/app/api/content/audio/route.ts`: narration stored in the content DB (`item_audio`), served only for published, allowed cards.
- `tests/redteam/content-cases.json`: unsafe content that must never publish.
- `src/lib/controls.ts`: per-child parent controls (Whyzy on/off, allowed modules, chat, show text); enforced in `/api/chat`, `/api/content` and the child page. Defaults: Whyzy off, chat off, audio only.
- `src/lib/retention.ts` + `src/app/api/cron/retention/route.ts`: daily retention job (Vercel Cron, `CRON_SECRET`).
- `docs/DATA_HYGIENE.md`: data hygiene checklist status.
- `OPERATOR_TODO.md`: things only the operator can do.
